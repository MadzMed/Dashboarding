# Projet Power BI — Conception d’un Dashboard

## Contexte

Vous travaillez en groupe de **4 personnes maximum**.

L’objectif est de concevoir un **dashboard Power BI clair, lisible et utile à la prise de décision**, puis de le présenter en **5 à 10 minutes maximum**.

Le dashboard doit permettre de comprendre rapidement les informations importantes du jeu de données et de faire ressortir un message principal.

---

## Objectifs

Votre travail doit montrer votre capacité à :

- sélectionner des indicateurs pertinents ;
- construire des visualisations adaptées à la question posée ;
- hiérarchiser l’information ;
- créer un dashboard lisible et cohérent ;
- utiliser les interactions de Power BI de manière pertinente ;
- créer des mesures en **DAX** ;
- construire un récit à partir des données ;
- présenter clairement les principaux enseignements.

---

# Travail demandé

## 1. Définir une problématique

Votre dashboard doit répondre à une **question claire**.

Exemples :

> Comment le phénomène étudié évolue-t-il dans le temps ?

> Quelles catégories ou zones géographiques se distinguent ?

> Quels sont les principaux facteurs à surveiller ?

La problématique doit guider vos choix de KPI, de graphiques et de filtres.

---

## 2. Préparer les données

Avant de construire le dashboard, vérifiez que les données sont exploitables.

Vous pouvez notamment :

- corriger les types de données ;
- traiter les valeurs manquantes ;
- supprimer les colonnes inutiles ;
- harmoniser les catégories ;
- créer des colonnes utiles à l’analyse ;
- fusionner plusieurs fichiers si nécessaire.

Les transformations peuvent être réalisées avec **Power Query**.

---

## 3. KPI et DAX

L’utilisation de **DAX est obligatoire**.

Votre dashboard doit contenir plusieurs mesures DAX pertinentes.

Selon votre sujet, vous pouvez par exemple calculer :

- total ;
- moyenne ;
- taux ou pourcentage ;
- évolution ;
- comparaison avec une période précédente ;
- classement ;
- indicateur conditionnel ;
- Top N.

Les mesures doivent avoir une utilité dans l’analyse et ne pas être ajoutées uniquement pour complexifier le projet.

---

# Conception du dashboard

Le dashboard doit être pensé pour être compris rapidement.

Portez une attention particulière à :

- la hiérarchie visuelle ;
- l’alignement ;
- les espaces ;
- le contraste ;
- la cohérence des couleurs ;
- la lisibilité des titres ;
- la mise en avant des KPI principaux.

Évitez de surcharger les pages.

Chaque graphique doit répondre à une question précise.

---

## Choix des visualisations

Choisissez le type de graphique en fonction de l’information à communiquer.

Votre dashboard doit permettre, lorsque les données le permettent, de comprendre :

- la situation générale ;
- les évolutions ;
- les différences entre catégories ;
- les éléments les plus importants ;
- les éventuelles anomalies ou tendances.

Les visualisations doivent être justifiées par le besoin d’analyse.

---

## Interactivité

Utilisez les fonctionnalités interactives de Power BI lorsqu’elles apportent une réelle valeur :

- segments ;
- filtres ;
- interactions entre visuels ;
- drill-down ;
- drill-through ;
- info-bulles ;
- signets ;
- navigation entre les pages.

L’interactivité doit faciliter la lecture et l’exploration du dashboard.

---

# Storytelling

Votre dashboard doit raconter une histoire.

Il doit permettre de répondre progressivement à trois questions :

1. **Que se passe-t-il ?**
2. **Où, quand ou pour quelles catégories ?**
3. **Quelle information importante doit-on retenir ?**

Les titres, KPI et graphiques doivent aider à faire ressortir ce message.

---

# Cas pratiques et sources de données

Les sujets ci-dessous sont proposés comme exemples.

Vous pouvez utiliser ces données ou choisir **un autre sujet et un autre dataset**.

Votre jeu de données doit simplement être suffisamment riche pour permettre une vraie analyse et la création de plusieurs indicateurs.

# Livrables

Chaque groupe doit fournir :

- le fichier **Power BI `.pbix`** ;
- les éventuels fichiers de données nécessaires au projet.

---

# Présentation orale

Chaque groupe dispose de **5 minutes maximum**.

La présentation doit aller directement à l’essentiel.

Présentez :

1. le sujet et la problématique ;
2. les principaux KPI ;
3. le dashboard et ses interactions importantes ;
4. **2 à 3 enseignements issus des données** ;
5. la conclusion principale.

Ne vous contentez pas de décrire les graphiques : expliquez ce qu’ils permettent de comprendre.

---

# Évaluation

L’évaluation portera principalement sur :

- la pertinence de la problématique ;
- la qualité des KPI ;
- l’utilisation pertinente de **DAX** ;
- le choix des visualisations ;
- la hiérarchie visuelle ;
- la lisibilité et la cohérence graphique ;
- l’interactivité ;
- le storytelling ;
- la capacité à faire ressortir les informations importantes ;
- la qualité de la présentation orale ;
- le respect des **5 minutes**.

---

# Rappel

Un bon dashboard ne cherche pas à montrer le maximum de graphiques.

Il cherche à faire comprendre rapidement **les bonnes informations, dans le bon ordre, pour le bon utilisateur**.
